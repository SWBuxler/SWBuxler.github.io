Project QQQ

AI-enabled VOIP transcription, sentiment, and extraction.

Date Made
Summer 2026
Technologies
Python, Django, Amazon Transcribe, OpenAI GPT, Vue.js

The problem

Our customer needed a way to analyze phone calls made between grain originators and farmers and extract usable insights. They wanted to be able to automatically detect data points from recordings of phone calls and pull those data points into the app. This would require a robust architecture incorporating LLM API calls, VoIP providers, and operations performed asynchronously from the user - and the task fell to me to build it.

What I built

The structure I built consisted of three conceptual portions. The first was the call and recording provider, which could retrieve call recordings from an individual company's external VoIP API or initiate and record calls from within our app itself. The second was the transcription process, which utilized Amazon's transcription services to asynchronously generate transcripts from the recordings produced by the first step. Finally, the pipeline utilized LLM calls to clean the input intelligently and extract observations in a format that could be used by other portions of the app. The whole pipeline took motion in a series of asynchronous tasks, separating the user from the timing issues of the backend operations.

Challenges

In making this pipeline usable for different customers with different VoIP providers, I implemented a hexagonal architecture that allowed each step of the pipeline to be swapped out for a different implementation based on who was using the app. Backfilling was another big part of the puzzle - our customer had a database of thousands of phone calls, and I had to create a system to process large chunks of past data without the user suffering performance issues. To do this, I created administrative commands to allow the backfill call processing to occur in quiet, controllable intervals.

The most persistent headache during development, however, was the problem of partially complete records. Throughout development, internal records would accumulate errored and partial runs of the transcription/analysis pipeline. The ability to manually run individual stages of the pipeline on a set of records was my solution to this issue, but it was still only a partial one, and the problem persisted in various forms across the development of the feature.

What I learned

The VoIP pipeline was my most ambitious project yet, with a large scope and clear customer impact. It was also the first feature that I built with extensive use of generative AI assistants such as Claude Code. I learned how to use LLM tools as a force multiplier, while also getting first-hand experience with their limitations. I also exploited asynchronicity for the first time in a production setting by creating custom Celery tasks to transcribe and process call transcripts.
