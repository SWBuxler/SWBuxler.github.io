How far to push the terminal

Twenty ways to carry the Terminal design further into the site. The interactive ones below are real — type in them. Your three questions answered first.

Should we have terminal tabs?

No. Tabs mean several things open at once; the site has three pages. They'd eat vertical space on mobile and imply state that doesn't exist. Take the window chrome instead (idea 01) — same signal, does real work by showing the path.

Should you be able to type, with autocomplete?

Yes — but layered over normal clickable navigation, never as the only way through. It's the single most credible "this person actually lives in a terminal" signal on the whole site. Ideas 05–08. If a recruiter never types, they lose nothing.

Can we use 08, the typed hero?

Yes, with one condition. It has to finish fast and never replay, and the text must be in the HTML so it's readable with JS off. Idea 09. Note the intro already opens with a story beat — typing both would be one flourish too many.

    What I'd take

    The failure mode is a site that's about being a terminal instead of about Seth. The defence is simple: take the ideas that do a job, skip the ones that only do a look.

    Take these five 01 window chrome · 03 status line on project pages · 06 ⌘K palette · 11 experience as git log · 18 phosphor glow. Every one earns its place — chrome shows the path, the status line is a progress bar, the palette is faster navigation, git log fits the content exactly, and the glow fixes the starkness.
    Then, if you want the flourish 05 + 07 + 08 — the command line with ghost autocomplete, Tab cycling and persistent history. This is the one that makes an engineer sit up. Build it after the content is done, and only if the résumé and write-ups are already finished.
    Free wins whenever 17 the 404 page, 15 the download transfer bar, 14 vim keys. None of them cost a recruiter anything, because none of them are load-bearing.

    Three rules

    1. Nothing is reachable only by typing. Every command has a link that does the same thing. The prompt is an accelerator, not a gate.
    2. The joke never costs a recruiter time. No boot delay, no download that waits on an animation, no content behind a command.
    3. Pick formats that fit the content. git log for a career and a man page for a write-up work because the structure is genuinely right. top for skills is a costume — it invites an argument about numbers you made up.
